🐸 BlockFrogs preview Blockfrogs v3.3 renderer (3.3.0, E3 delegate master) · nothing is inscribed

Type Bitmap block heights, then press Render. Every v3.3 trait comes from the block height alone. Each frog is drawn by the real blockfrogs-child.v3.3.html master (a PREVIEW build of it, using its own ?h= override) in two hosts: a plain browser, which runs its own three.js view, and the official MML web client, which runs its MML path.

Up to 6 heights, comma- or space-separated. Each frog uses 2 WebGL views.

Block data (info only)

v3.3 derives every trait from the Bitmap height N (body layers from its digits, special traits from divisibility, palindromes, squares and digit strings), so nothing depends on a block hash and there is no confirmation-hash input any more. Block data is shown for context and used for the tip ("latest", future-block check).

Local preview only. Block data is fetched live from ordinals.com or mempool.space (both send Access-Control-Allow-Origin: *). Renderer: blockfrogs-child.v3.3.html (v3.3.0) with 7 marked /*PREVIEW HOOK*/ lines (5 hook points) plus PREVIEW = true; its trait, mint-rule and validation code is byte-identical to the source. Models come from glb/ (the 63 glb-min files; every v3.3 part has a model) through preview inscription ids (ids-map.json). Mint validation (parents, CBOR metadata, collection parent) does not run in preview mode. three.js is r178 from lib/. The MML client is mml-client.min.js, built from @mml-io/mml-web 0.26.1. No CDN is used.
